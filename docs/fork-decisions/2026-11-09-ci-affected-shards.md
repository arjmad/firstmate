2026-11-09: Arjun said "run fewer checks on small prs" in the helm, because every pull request ran all of CI's 27 jobs for 20 to 25 minutes and seven pull requests queued about two hours under the account's concurrent-job cap.
Decision: a pull request runs only the lint partitions and behavior scripts its change touches, every unaffected check still reports success under its own name, and pushes, `workflow_dispatch`, the `full-ci` label, CI configuration, shared libraries, broadly sourced files, more than 25 changed files, deletions under `bin/` or `tests/`, and unmapped paths run the full suite.
Why: replaying the forty merged pull requests before this change, most selected 50 to 300 of about 300 behavior scripts and touched 13 to 16 of 16 behavior lanes, so skipping whole untouched lanes would have saved little; running only the selected scripts inside a touched lane is where the time goes.
The two thresholds are measured: merged pull requests ran 1 to 16 changed files over those forty, so more than 25 sends only sweeps to the full suite, and over the 563 canonical lint roots the non-library files sourced by more than 8 others are `fm-backend.sh` (56), `herdr-test-safety.sh` (18), `wake-helpers.sh` (17), `backends/herdr.sh` (10), `fm-operational-input.sh` (9) and `fm-afk-contract.sh` (9), with the next at 6, so a broadly sourced file is one sourced by more than 8.
Upstream at 14d06b04 has no changed-file or path filter, so this is a fork patch; its label concurrency group and `Not run for label - ` name prefix are ported from upstream's outside pull request gate.
No upstream proposal yet: upstream's runners and contributor gate differ, and the plan rides on this fork's eight lint partitions and thirteen serial shards.
