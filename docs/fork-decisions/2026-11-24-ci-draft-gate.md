2026-11-24: Arjun approved audit item a1-32 in the 2026-11-19 deep audit walk, because 39 of 77 pull request runs were cancelled by a newer push and those cancelled runs spent about 4,460 job-minutes, as much as the 24 successful runs.
Decision: a draft pull request runs only the quick checks and a failing `Ready for review` verdict that says to mark it ready, while its lanes and `Full suite` skip, marking it ready runs the full suite once on its head, and a draft's runs keep a concurrency group of their own so a late draft run cannot cancel that one full run; firstmate's own pull requests stay drafts until their reviews are done.
Why: review-fix pushes are what supersede most runs, and the fleet repository's gate cut its cancelled runs the same way (https://github.com/arjmad/fleet/pull/1177); the failing verdict keeps a draft head from reading as fully tested, since this fork has no required checks and `bin/fm-pr-merge.sh` reads only the checks that reported.
The verdict is its own job with no `needs`, because GitHub creates the `Full suite` check only once its lanes finish, so a draft failure carried there would stay red for most of the ready run.
GitHub can also start a draft event's run after the ready run on the same head, so every job a draft skips takes a `Not run for draft - ` name prefix and its skipped check never replaces the ready run's.
The verdict reads only the event's draft flag and fails closed in that case, because rereading the live pull request would pass a late draft run before the ready run's checks exist and could let an untested head merge; rerunning the verdict job in the ready run clears the stale failure.
Upstream at 427056c4 has no draft condition, so this is a fork patch.
