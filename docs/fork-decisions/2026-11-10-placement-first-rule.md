2026-11-10: Arjun, in the helm chat, asked "if fafnir is unavailable for any reason can we have it fall back to heimdall if the placement rule says to go to faf?" and, shown the design (Fafnir first, Heimdall fallback when Fafnir is unreachable, its second mate is down, or it has no free slot; the reason recorded on the task; told once; a task already running on Fafnir never restarted on Heimdall; gaming not unavailable), answered "yes".
Decision: placement by rule extends the intake spill rather than adding a router: a `first <secondmate-id> <project>...` line in `config/intake-spill` sends those projects' fresh ships and scouts to one remote secondmate first, `bin/fm-intake-spill.sh --project` reads its liveness and free slots over the existing `bin/fm-on.sh` route, and `bin/fm-spawn.sh` refuses a local spawn that rule sends to an available secondmate.
Free slots count memory and the lane ceiling only, so CPU load from a game never makes the secondmate unavailable.
